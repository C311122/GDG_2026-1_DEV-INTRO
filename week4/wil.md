# Git Flow vs GitHub Flow

## 1. Git Flow 

### 브랜치 구조
1.  **`main`**: 제품으로 출시될 수 있는 상태의 코드만 관리합니다. (항상 안정적이어야 함)
2.  **`develop`**: 다음 출시 버전을 개발하는 중심 브랜치입니다.
3.  **`feature`**: 기능을 개발하는 브랜치입니다. `develop`에서 따오고 작업 후 다시 `develop`으로 합칩니다.
4.  **`release`**: 배포를 준비하는 브랜치입니다. 버그 수정 및 버전을 확정하며, 완료 후 `main`과 `develop`에 합칩니다.
5.  **`hotfix`**: 배포된 버전(`main`)에서 발생한 긴급 버그를 즉시 수정하기 위한 브랜치입니다.

### 장점 및 적합한 환경
* **장점**: 배포 버전 관리가 매우 명확하며, 대규모 인원이 협업할 때 안정성이 높습니다.
* **추천 프로젝트**: 모바일 앱, 패키지 소프트웨어, 정기적인 업데이트 주기가 있는 서비스.

## 2. GitHub Flow

### 주요 작업 흐름
1.  **브랜치 생성**: `main`에서 새로운 브랜치를 생성합니다. 
2.  **커밋 및 푸시**: 작업 후 로컬에 커밋하고 원격 서버에 푸시합니다.
3.  **Pull Request (PR) 생성**: 코드 리뷰를 요청하고 팀원들과 토론합니다.
4.  **Merge 후 즉시 배포**: 리뷰가 끝나면 `main`에 합치고, 즉시 실제 서비스에 배포합니다.

### 장점 및 적합한 환경
* **장점**: 구조가 단순하여 관리가 쉽고, 빠른 피드백과 수시 배포가 가능합니다.
* **추천 프로젝트**: 실시간 업데이트가 잦은 웹 서비스, 소규모 팀, 애자일 조직.

## 비교표

| 비교 항목 | Git Flow | GitHub Flow |
| :--- | :--- | :--- |
| **복잡도** | 높음 (5가지 브랜치) | 낮음 (main + feature) |
| **중심 브랜치** | `main`, `develop` | `main` |
| **배포 방식** | 정기 (묶어서 배포) | **수시 (작업 완료 시 즉시 배포) |
| **코드 리뷰** | 선택적 | 필수 (PR 기반) |
| **핵심 가치** | 안정성, 버전 관리의 명확성 | 빠른 개발, 지속적 배포(CI/CD) |

# Commit Convention

## 1. 커밋 메시지 구조

기본적으로 **제목, 본문, 꼬리말** 세 부분으로 구성하며, 각 부분 사이에는 빈 줄을 넣어 구분합니다.

> type(scope): subject  <-- 제목 (필수)
>
> body                  <-- 본문 (선택)
>
> footer                <-- 꼬리말 (선택)


## 2. 제목(Header) 작성 규칙

제목은 커밋의 핵심 내용을 요약합니다.

### Type (타입)
가장 자주 쓰이는 타입들입니다.

| 타입 | 설명 |
| :--- | :--- |
| **feat** | 새로운 기능 추가 |
| **fix** | 버그 수정 |
| **docs** | 문서 수정 (README, Swagger 등) |
| **style** | 코드 포맷팅, 세미콜론 누락 등 (로직 변경 없음) |
| **refactor** | 코드 리팩토링 (기능은 동일하지만 구조 개선) |
| **test** | 테스트 코드 추가 및 수정 |
| **chore** | 빌드 설정, 패키지 매니저 수정 등 기타 작업 |
| **perf** | 성능 개선 |

### Subject (제목 요약)
- 50자 이내로 간결하게 작성합니다.
- 마지막에 마침표(.)를 찍지 않습니다.
- 과거형보다는 명령문/현재형 동사를 사용합니다.
  - (O) Add login logic
  - (X) Added login logic / Adding login logic

## 3. 본문(Body) 및 꼬리말(Footer)

### Body (본문)
- 왜(Why) 그리고 무엇을(What) 변경했는지에 대해 상세히 설명합니다.
- 어떻게(How) 보다는 배경과 의도를 설명하는 데 집중합니다.

### Footer (꼬리말)
- 이슈 트래커 ID를 참조할 때 사용합니다.
- 예: `Fixes: #123`, `Related to: #45`

## 4. 작성 예시

### 기능 추가 (feat)
> feat(auth): JWT 로그인 기능 및 토큰 검증 로직 구현
>
> - 로그인 시 Access Token 및 Refresh Token 발급 로직 추가
> - Spring Security Filter 내 JWT 검증 로직 구현
> - 회원가입 시 비밀번호 BCrypt 암호화 적용
>
> Resolves: #24

### 버그 수정 (fix)
> fix(api): 상품 리스트 조회 시 페이징 오류 수정
>
> - Pageable 객체의 offset 계산이 잘못되던 문제 해결
> - 0페이지 이하 요청 시 예외 처리 로직 추가
>
> Fixes: #10
